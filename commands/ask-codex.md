# Ask Codex

Claude와 Codex가 **서로의 답을 보지 못한 상태에서** 각자 답하고, 그 뒤 한 차례 교차 반론합니다. 이 세션의 Claude는 참가자가 아니라 심판입니다.

## 설계 원칙 (어기면 교차 검증이 성립하지 않음)

- **오케스트레이터는 참가자가 아니다.** 이 세션의 Claude는 R0 답변 두 개를 받기 전에 스스로 결론을 만들지 않습니다. 초안을 쓰지 않습니다.
- **Claude 측 답변은 반드시 서브에이전트가 만든다.** 오케스트레이터가 자기 답을 Claude 입장으로 제출하면 심판과 참가자가 같아집니다.
- **R0는 블라인드다.** 어느 쪽에도 상대의 답변이나 오케스트레이터의 의견을 넘기지 않습니다. 한쪽 답이 먼저 노출되면 다른 쪽이 앵커링됩니다.
- **이견은 병합하지 않는다.** 합의되지 않은 지점은 한쪽으로 정리하지 말고 양쪽 입장과 근거를 그대로 병기하고, 판단은 사용자에게 넘깁니다.

## 입력

`$ARGUMENTS`

- 선행 `--model <MODEL>`이 있으면 해당 Codex 모델을 사용합니다.
- 모델을 지정하지 않으면 `gpt-5.6-sol`을 사용합니다.
- 질문이 없으면 사용자에게 질문을 요청하고 중단합니다.

## 실행

### R0 — 블라인드 독립 답변

두 호출을 **같은 메시지에서 동시에** 실행합니다 (순차 실행하면 대기 시간만 늘어납니다).

**(a) Claude 참가자** — `Agent` 툴로 서브에이전트를 띄우고 **질문만** 전달합니다. 오케스트레이터의 해석이나 추측을 덧붙이지 마세요. 리포 코드에 관한 질문이면 서브에이전트가 직접 파일을 읽고 근거를 확보하도록 지시합니다.

**(b) Codex** — 질문 문자열을 셸 명령에 직접 삽입하지 말고 stdin으로 전달합니다.

```bash
codex exec --model "<MODEL>" --sandbox read-only --skip-git-repo-check --json - <<'CODEX_PROMPT'
다음 질문에 독립적으로 답하라. 결론과 근거를 간결하게 제시하고, 확신이 낮은 부분은 명시하라.

질문:
<QUESTION>
CODEX_PROMPT
```

JSONL에서 `type == "thread.started"` 이벤트의 `thread_id`, 그리고 마지막 `type == "item.completed"` 중 `item.type == "agent_message"`인 항목의 `item.text`를 Codex 답변으로 취합니다.

### R1 — 교차 반론

양쪽 R0 답변이 모두 도착한 뒤에만 시작합니다. 각자에게 **상대 답변만** 전달하고 반론을 받습니다. 이때도 오케스트레이터의 판단은 넣지 않습니다.

**(a) Claude 참가자** — R0를 맡은 서브에이전트에 `SendMessage`로 이어서 Codex 답변을 전달합니다. 이어가기가 안 되면 새 서브에이전트에 [질문, 자기 R0 답변, Codex R0 답변] 세 가지를 모두 넘깁니다.

**(b) Codex** — 같은 세션에 이어서 전달합니다.

```bash
codex exec resume --model "<MODEL>" --skip-git-repo-check --json "<THREAD_ID>" - <<'CODEX_FOLLOWUP'
다음은 같은 질문에 대한 다른 모델의 독립 답변이다. 네 답변과 비교해 수용할 점과 유지할 이견을 구분하고, 최종 입장을 제시하라.

상대 답변:
<CLAUDE_R0>
CODEX_FOLLOWUP
```

양쪽에 같은 지시를 주어야 합니다. 한쪽에만 "반박하라", 다른 쪽에 "검토하라"처럼 비대칭 지시를 주면 결과가 기웁니다.

### 종합

R1 결과 두 개를 놓고 합의점과 남은 이견을 분류합니다. 사실관계가 갈리고 리포에서 확인 가능한 항목이면 이때 직접 파일을 읽어 확인하고, 어느 쪽이 맞았는지 근거와 함께 밝힙니다.

## 최종 답변 형식

- 사용자의 질문에 대한 직접적인 결론부터 제시합니다.
- **합의**: 양쪽이 동의한 내용. 출처를 굳이 구분하지 않습니다.
- **남은 이견**: 양쪽 입장과 각 근거를 병기합니다. 한쪽으로 정리하지 말고, 무엇을 확인하면 결론이 나는지 적습니다.
- 이견이 없으면 이견 항목을 생략합니다. 억지로 만들지 않습니다.
- 원시 JSONL, 서브에이전트 원문, 비공개 추론 과정은 노출하지 않습니다.
- 파일을 수정하지 않습니다.

## 호출 규칙

- Codex 호출은 최대 두 번(R0 + R1)입니다.
- `resume`에는 `--sandbox` 옵션이 없습니다. 첫 호출의 샌드박스 설정이 세션에 유지되므로 재개 호출에 붙이지 마세요.
- 질문이나 답변 본문에 heredoc 종료 토큰(`CODEX_PROMPT` / `CODEX_FOLLOWUP`)과 똑같은 줄이 있으면 충돌하지 않는 다른 토큰으로 바꿉니다.

## 실패 처리

- **Codex R0 실패**: 원인을 알리고 중단합니다. 한쪽만으로는 교차 검증이 아닙니다.
- **Codex R1만 실패**: 양쪽 R0까지를 근거로 종합하고, 반론 라운드가 없었음을 밝힙니다.
- **Claude 서브에이전트 실패**: 오케스트레이터가 직접 Claude 측 답변을 만들되, 심판과 참가자가 같아졌다는 사실을 최종 답변에 명시합니다.
